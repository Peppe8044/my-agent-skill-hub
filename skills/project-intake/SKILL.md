# project-intake

## Procedure
1. Ask only missing essential questions; use available user context, do not repeat answered questions.
2. Write one-sentence problem and measurable outcome; identify personas, workflows, input/output and dependencies.
3. Define MVP, exclusions, nonfunctional requirements (security, privacy, availability, volume, latency, maintenance, cost).
4. Mark assumptions, unknowns and what would change architecture. Define testable acceptance criteria and owner.
5. Save PROJECT_BRIEF.md, TASK_PLAN.md; avoid choosing frameworks before acceptance requirements are clear.
6. Route to stack-selection then solution-architect for approval.

## Final gate
Follow `AGENTS.md`; update `WORK_LOG.md` with real evidence on all material tasks. Follow `token-budget` to minimize excess calls while preserving quality. If a process rule is waived, record user approval, scope, risk and compensation in `EXCEPTIONS.md`.
