# ADR-0004: Instalador con deduplicación de MCP y preservación de archivos

- Estado: Aceptada
- Fecha: 2026-11-27
- Contexto: `install` por defecto escribía definiciones MCP de GitHub y ClickUp aunque el usuario ya tuviera servidores equivalentes (por ejemplo `claude.ai ClickUp` ya conectado como conector), y el README afirmaba "No activa MCP, hooks ni ejecuta código externo", lo que contradecía el comportamiento real (se copia el hook `model_guard` y se declaran servidores MCP). Además, los archivos JSON de configuración del proyecto no deben perderse ni sobrescribirse.
- Opciones: (A) mantener el perfil `full` por defecto, con deduplicación de MCP y preservación; (B) cambiar el perfil por defecto a `core` y exigir `--profile full` para MCP y política; (C) `full` sin deduplicar.
- Decisión: A. `full` sigue siendo el perfil por defecto: copia agentes, skills, `MODEL_POLICY.json` y el hook `model_guard`; fusiona `.claude/settings.json` conservando claves y hooks del proyecto (añade `env.CLAUDE_CODE_SUBAGENT_MODEL: sonnet` si falta; un valor fuera de sonnet/haiku es conflicto de política); declara los servidores HTTP de GitHub y ClickUp en `.mcp.json` solo si no existe uno equivalente (mismo nombre normalizado o URL) en el `.mcp.json` del proyecto, el ámbito usuario/local (`~/.claude.json`) o la lista de runtime de `claude mcp list` (incluye conectores claude.ai); los duplicados omitidos se listan en el informe y los servidores existentes nunca se eliminan ni reescriben; `--no-runtime-mcp-scan` omite `claude mcp list`. Los archivos modificados por el proyecto nunca se sobrescriben: la versión del hub queda en `.agent-hub/incoming/<ruta>`, se lista en `conflicts` y `bootstrap` informa `ready: false` hasta reconciliar. Los conflictos de política (settings con modelo no opus o variables prohibidas) detienen la instalación antes de escribir. El código upstream de `external/` (hooks, instaladores, MCP) nunca se activa; el único hook instalado es `model_guard`. El README se corrige para describir esto.
- Consecuencias: instalación idempotente y sin MCP duplicados; el comportamiento depende de lo que `claude mcp list` devuelva en la máquina (puede variar entre equipos); declarar un servidor no lo autentica, Claude Code pide aprobación antes de usar servidores MCP del proyecto y las credenciales siguen siendo locales. Frente a "core por defecto": `full` entrega la política de modelos y las integraciones esperadas desde el primer comando, y la deduplicación elimina su principal riesgo (conflictos con configuración existente) sin perder el valor del bootstrap de un solo paso; quien no quiera MCP ni política local puede usar `--profile core`.
- Evidencia: tests del instalador y docs/QUALITY_REPORT.md; docs/INTEGRATION_BOOTSTRAP.md.
- Revisión: si aparecen nuevos ámbitos de configuración MCP o cambia el formato de `claude mcp list`.
